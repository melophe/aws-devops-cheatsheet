# ネットワークと DR（Route 53 / CloudFront / ELB / DR の考え方）

## Route 53

- ルーティングは、シンプル / 加重 / レイテンシー / フェイルオーバー / 地理的 / 地理的近接性 / マルチバリュー
- エイリアスレコードは、別のレコードセットや AWS リソースを指せる。「ターゲットの正常性の評価」を有効にすると、参照先の異常が伝わる（レコードを階層にしたときは、各層で有効にする）
- レコードを変更しても、リゾルバーのキャッシュには、古い TTL の間、旧情報が残る。旧環境を止めるのは、旧 TTL が経ってから
- プライベートホストゾーンは、VPC に関連付けないと解決できない。VPC の enableDnsSupport と enableDnsHostnames も有効にする
- 別アカウントの VPC に関連付けるには、ホストゾーン側で認可を作成してから、VPC 側で関連付ける
- Resolver 本体は、VPC の +2 のアドレスで常に動く。インバウンドエンドポイントは、オンプレ → AWS の問い合わせ。アウトバウンドエンドポイントは、AWS → オンプレの問い合わせ
- Application Recovery Controller: ゾーンシフトは、AZ 単位・期限付きで、トラフィックを切り離す。ルーティングコントロールには、アサーションルール（対象自身の状態に条件）とゲーティングルールがある

## CloudFront

- オリジングループは、プライマリが 5xx などを返したら、リクエスト単位でセカンダリに再試行する（DNS の伝播待ちがない）
- Origin Shield は、キャッシュミスを集約して、オリジンの負荷を減らす
- 継続的デプロイは、ステージングのディストリビューションで、一部のトラフィックを検証できる
- Lambda@Edge は、ビューワー側とオリジン側（キャッシュミス時）のイベントを扱える。CloudFront Functions は、ビューワー側のみ
- キャッシュは、TTL が切れるまで残る。すぐ更新したいときは、明示的な無効化（CreateInvalidation）

## ELB と Global Accelerator

- ALB は L7。スティッキーセッション（LB 生成の Cookie）、加重ターゲットグループ、リスナールールが使える。EIP は付けられず、WAF は関連付けられる
- NLB は L4。EIP が使える。Cookie によるスティッキーはない
- クロスゾーン負荷分散は、ALB では既定で有効で、ターゲットグループ単位で上書きできる。ゾーンシフトで AZ を完全に切り離すには、無効にする
- Global Accelerator は、Anycast の静的 IP が 2 つ。AWS のバックボーンに早く入れる。エンドポイントは ALB / NLB / EC2 / EIP。DNS のキャッシュに依存しない。API Gateway は対象外
- ALB を dualstack にすると、IPv6 で受けて IPv4 で EC2 に転送する（EC2 側は変更不要）。VPC とサブネットに IPv6 CIDR が要る
- API Gateway のエンドポイントは、エッジ最適化 / リージョナル / プライベート。マルチリージョンで独立稼働させるなら、リージョナルを各リージョンに作り、Route 53 のレイテンシールーティングで振り分ける

## DR の考え方

- RPO（失ってよいデータの時間）と RTO（復旧までの時間）で方式を選ぶ。バックアップ＆リストア / パイロットライト / ウォームスタンバイ / マルチサイト
- RDS の Multi-AZ は、同期レプリケーションと自動フェイルオーバーで、単一リージョン。クロスリージョンのリードレプリカは非同期で、昇格してスタンドアロンにできる
- Aurora のグローバルデータベースは、秒未満のレプリケーション。セカンダリを昇格する。rds.global_db_rpo で、RPO の目標を設定する
- AWS Backup は、プランとボールト。クロスリージョン／クロスアカウントのコピーは、1 時間規模の遅れがある。クロスアカウントは、コピー先ボールトのアクセスポリシーと、暗号化キー（CMK）のキーポリシーの両方で許可する
- S3 のクロスリージョンレプリケーションは、バージョニングが必須。設定後の新規オブジェクトが対象で、既存分はバッチレプリケーション。S3 RTC は、15 分以内の複製 SLA。マルチリージョンアクセスポイントは、単一のエンドポイントを提供する
- 双方向にしたいときは、ソースと宛先を逆向きにもルールを作る。バッチレプリケーションのロールの信頼ポリシーには、s3.amazonaws.com と batchoperations.s3.amazonaws.com
- DynamoDB のグローバルテーブルは、複数リージョンで読み書きできる
- FSx for ONTAP は、SnapMirror でボリューム単位に複製する（クラスターピアリングと SVM ピアリングが前提）。SMB と NFS を、同じボリュームで提供できる
- ECR のレプリケーションは、設定後の新規イメージのみ。CodeCommit は、別リージョンへのミラーを自分で組む（EventBridge ＋ CodeBuild）

## ネットワーク接続

- Direct Connect の仮想インターフェイスは、プライベート VIF（VPC）、パブリック VIF（AWS のパブリックサービス）、トランジット VIF（Transit Gateway）
- BGP とルート伝播を使うと、オンプレの CIDR が増えても、ルートテーブルに自動で反映される
- 短納期・低帯域・冗長化が必要なら、Site-to-Site VPN を 2 本。Direct Connect は、回線の手配に時間がかかる
- Transit Gateway は、ルートテーブルを分けて、セグメント化できる（経路が無ければ届かない）。RAM で共有でき、アタッチメントは各アカウントが作る（自動受け入れを有効にすると、承認待ちがなくなる）
- VPC 共有は、RAM でサブネットを他のアカウントに共有する。VPC が 1 つなので、VPC 間の接続は要らない
- Gateway Load Balancer は、アプライアンスを透過的に挟む（GENEVE）。検査用の VPC に GWLB とアプライアンス、各 VPC に GWLB エンドポイントを置き、ルートテーブルのネクストホップに指定する
- ゲートウェイ型の VPC エンドポイントは、S3 と DynamoDB のみ。それ以外はインターフェイス型（PrivateLink）
- NAT ゲートウェイは、AZ ごとに作り、ルートテーブルも AZ ごとに用意する
- WorkSpaces のリージョン冗長は、接続エイリアス（共通の接続文字列）と Route 53 のフェイルオーバーで、登録コードを変えずに切り替える
- AWS の外のデバイスの MQTT は、IoT Core（カスタムドメインで独自のドメインを使える）。エッジで動かし続けるなら Greengrass

## ストレージと DB の補足

- EBS のスナップショットの自動化は、Data Lifecycle Manager（DLM）で、タグを対象に、日次の取得、保持、クロスリージョンコピーのルールを作れる。EBS だけなら DLM が軽く、EC2・RDS・EFS などをまとめて管理するなら AWS Backup
- Aurora のエンドポイント: クラスターエンドポイント（書き込み。フェイルオーバーに追従する）、リーダーエンドポイント（読み取りを分散する）、インスタンスエンドポイント（個別。フェイルオーバーで手動の変更が要る）
- Aurora のクロスリージョンリードレプリカを、障害時に自動で昇格する: EventBridge で RDS のイベント（カテゴリ failure）を検知 → Lambda で PromoteReadReplicaDBCluster → 新しいエンドポイントを Parameter Store に反映する。FailoverDBCluster は同一クラスター内で、ModifyDBCluster では昇格できない
- Aurora のマイナーバージョンは、自動アップグレードを有効にすると、メンテナンスウィンドウ内で更新される。メジャーバージョンは手動で、事前にスナップショットと、テスト環境での検証を行う。ローリングは、リードレプリカを先に更新して昇格させ、旧ライターを更新する
- Lambda@Edge は、環境変数が使えず、VPC 内のリソースへ直接接続できず、us-east-1 でデプロイして、全エッジに配られる
- S3 の Glacier の取り出し: Glacier Instant Retrieval（ミリ秒）、Flexible Retrieval（数分〜数時間）、Deep Archive（約 12 時間）。Intelligent-Tiering にも、アーカイブ用の階層がある。ライフサイクルルールの AbortIncompleteMultipartUpload で、未完了のアップロードを削除できる
